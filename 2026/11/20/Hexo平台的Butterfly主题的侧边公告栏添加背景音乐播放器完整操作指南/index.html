Hexo平台的Butterfly主题的侧边公告栏添加背景音乐播放器完整操作指南

发表于2026-11-20|更新于2026-11-20|hexo

一 项目介绍

在使用 Hexo 搭建个人博客时，我们可以通过 Butterfly 主题自带的公告栏展示网站公告、个人介绍以及一些个性化内容。

本篇文章介绍如何在 Butterfly 主题的公告栏中添加一个简洁、美观的背景音乐播放器，让访问博客的用户在浏览文章时，可以听一首舒缓的音乐。

整个实现过程不需要安装 APlayer、hexo-tag-aplayer 等第三方插件，也不需要增加任何 npm 依赖，只需要使用 HTML、CSS 和原生 JavaScript 即可完成。

最终实现的播放器具有以下功能：

  • 使用本地 MP3 音频文件，不依赖第三方音乐平台。
  • 支持音乐播放和暂停。
  • 支持实时播放进度显示。
  • 支持手动拖动进度条。
  • 支持音量大小调整。
  • 默认音量设置为 35%。
  • 支持单曲循环播放。
  • 支持手动开启和关闭循环播放。
  • 页面加载时主动尝试自动播放。
  • 如果浏览器阻止自动播放，在用户首次与页面交互时再次尝试播放。
  • 适配 Butterfly 公告栏的浅色视觉风格。
  • 支持移动端布局。

整个播放器采用独立的 CSS 类名前缀和 JavaScript 闭包，尽量避免与 Butterfly 主题原有样式和脚本发生冲突。

七 自动播放和浏览器限制说明

这是整个音乐播放器中需要特别说明的地方。

很多用户会希望进入博客首页后，背景音乐能够自动播放。

但是，现代浏览器通常会限制未经用户交互的有声自动播放。

例如：

  • Chrome 可能阻止没有播放许可的有声自动播放。
  • Safari 通常要求用户与网页发生交互。
  • Firefox 也可能根据用户的自动播放设置阻止音乐播放。

因此，即使我们在 HTML 中添加：

也不能保证所有浏览器都能自动播放。

本文采用的是相对完善的处理方式：

  1. 页面初始化时主动尝试播放。
  2. 如果浏览器允许，则直接播放。
  3. 如果浏览器阻止，则等待用户第一次点击、触摸或按键。
  4. 用户与网页交互后，再次尝试启动音乐。
  5. 音乐开始播放后，根据循环播放开关决定是否重复播放。

需要明确的是，浏览器限制无法通过 JavaScript 彻底绕过。

如果访客的浏览器禁止有声自动播放，仍然需要用户进行一次有效交互。

10.1 音频文件会不会重复占用Git仓库空间

这里顺便说明一个常见问题。

如果你担心每次更新博客文章，都会让 6MB 的音频文件重新占用一次仓库空间，那么不需要担心。

Git 会对文件内容进行对象存储。

当音频文件内容没有发生变化时，后续提交不会重复保存一份完整的 6MB 音频文件。

例如：

操作 音频文件新增存储
第一次添加音频 约 6MB
修改一篇博客文章 基本不增加
修改主题 CSS 基本不增加
新增博客文章 基本不增加
修改 Hexo 配置 基本不增加
替换音频文件 可能增加约 6MB

因此，只要音频文件一直不变，就可以放心地正常提交和推送博客源码。

需要注意，Gitee 和 GitHub Pages 是两个独立仓库，各自保存自己的文件和历史记录。

10.1 为什么进入网站后没有自动播放音乐

这是浏览器自动播放限制导致的。

本文已经实现页面加载时主动尝试播放，以及用户首次与网页交互后再次尝试播放。

如果浏览器仍然禁止自动播放，就需要用户点击播放按钮。

这不是播放器代码错误，而是浏览器的安全策略。

十二 总结

通过 Butterfly 自带的公告栏功能，我们可以非常简单地为 Hexo 博客添加一个属于自己的背景音乐播放器。

整个实现只涉及三个核心文件：

  1. HTML 负责公告栏播放器结构。
  2. CSS 负责播放器外观。
  3. JavaScript 负责音乐播放和交互功能。

音频文件则直接放在主题的 source/img 目录中，由 Hexo 自动复制到最终生成的网站目录。

这种实现方式具有以下优点：

  • 不需要安装额外插件。
  • 不需要依赖第三方音乐平台。
  • 不需要配置音乐 API。
  • 不需要额外的 npm 依赖。
  • 音乐文件由自己管理。
  • 播放器样式可以自由修改。
  • 后期维护简单。

对于只需要在个人博客公告栏播放一首本地音乐的场景来说，这种方式已经足够轻量和实用。
