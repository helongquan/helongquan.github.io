Windows安装PHP和wp-cli配置全局命令高效管理wordpress站点及LocalWP实战指南

发表于2026-11-18|更新于2026-11-18|wordpress

在日常 WordPress 开发和维护过程中，经常需要通过命令行完成一些操作，例如：

  • 查看 WordPress 版本。
  • 查看已安装的插件和主题。
  • 更新插件和主题。
  • 启用或停用插件。
  • 检查 WordPress 数据库。
  • 执行 WordPress 数据维护操作。

这些操作都可以通过 WP-CLI 实现。

WP-CLI 是 WordPress 官方提供的命令行管理工具，可以直接通过终端管理 WordPress，不需要每次进入 WordPress 后台进行操作。

本文主要介绍如何在 Windows 电脑上独立安装 PHP 和 WP-CLI，实现以下目标：

  1. 在 Windows 上下载并安装 PHP。
  2. 配置 PHP 环境变量，使任何目录都可以执行 php 命令。
  3. 下载并安装 wp-cli.phar。
  4. 配置 WP-CLI 环境变量，使任何目录都可以执行 wp 命令。
  5. 配置 PHP 的 php.ini 文件，启用常用扩展。
  6. 不重启电脑，通过重启 Windows 资源管理器使环境变量生效。
  7. 理解 LocalWP 的环境隔离机制。
  8. 使用 LocalWP 自带的 Shell 管理 WordPress 网站。
  9. 利用 Windows CMD 的磁盘目录记忆功能，快速切换到 WordPress 网站根目录。

最终实现 Windows 全局 PHP 和 WP-CLI 环境，同时保留 LocalWP 自带的独立运行环境。

https://www.php.net/downloads.php

Windows 推荐下载 PHP 8.x 的 x64 版本，笔者下载的是PHP8.5。

这里需要注意 PHP 的版本类型：

  • VS16、VS17 等表示对应的 Visual Studio 编译版本。
  • x64 表示 64 位系统。
  • Thread Safe 表示线程安全版本。
  • Non Thread Safe 表示非线程安全版本。

如果只是为了在 Windows 命令行中运行 PHP 和 WP-CLI，通常选择 x64 Non Thread Safe 即可。

建议下载 ZIP 压缩包，不需要下载安装程序。

四、不重启电脑使环境变量立即生效

修改 Windows 环境变量后，很多教程会建议重启电脑。

实际上，大多数情况下没有必要。

Windows 中运行的程序会继承启动时的环境变量。因此，已经打开的 CMD、PowerShell 等程序不会自动获取最新的环境变量。

五、理解LocalWP的环境隔离机制

完成 Windows 全局 PHP 和 WP-CLI 安装后，还需要了解 LocalWP 的运行机制。

LocalWP 是一个本地 WordPress 开发环境工具，它会为本地网站提供独立的运行环境。

通常包括：

  • PHP 运行环境。
  • MySQL 数据库。
  • Web 服务器。
  • 网站运行配置。
  • 对应的开发工具。

这些环境由 LocalWP 自己管理，不一定使用 Windows 系统中安装的 PHP 和 MySQL。

5.1 Windows全局环境和LocalWP环境的区别

两套环境可以理解为：

对比项目 Windows全局环境 LocalWP环境
PHP 自己下载和配置 LocalWP 自己管理
MySQL 自己安装和配置 LocalWP 自己管理
WP-CLI 自己下载配置 LocalWP 提供运行环境
使用范围 Windows 全局终端 LocalWP 对应站点
环境配置 自己维护 LocalWP 管理

因此，即使 Windows 全局 PHP 已经安装成功，也不代表它能够直接连接 LocalWP 的 MySQL 数据库。

5.2 为什么建议使用LocalWP自带的Shell

如果需要查询某个 WordPress 网站的信息，例如：

  • 查看插件列表。
  • 查看主题列表。
  • 查看 WordPress 版本。
  • 检查数据库。
  • 更新插件。
  • 执行数据库操作。

建议优先进入 LocalWP 对应网站的 Shell 环境。

操作步骤：

  1. 打开 LocalWP。
  2. 找到需要操作的 WordPress 网站。
  3. 确保网站处于 Running 状态。
  4. 点击 Open Site Shell。
  5. 在打开的终端中执行 WP-CLI 命令。

十、总结

通过本文的配置，我们完成了 Windows 环境下 PHP 和 WP-CLI 的独立安装，并实现了全局命令调用。

整个方案最重要的是理解两套环境的区别：

  • Windows 全局 PHP 和 WP-CLI 是自己安装和维护的。
  • LocalWP 自带独立的 PHP、MySQL 和网站运行环境。
  • Windows 全局环境适合执行通用 PHP 和 WP-CLI 命令。
  • LocalWP Shell 更适合管理 LocalWP 中实际运行的 WordPress 网站。

另外，通过 CMD 的磁盘目录记忆功能，还可以快速返回之前使用过的 WordPress 网站根目录。

这样既保留了 Windows 全局命令行工具的便利性，也避免了 LocalWP 内部环境和 Windows 全局环境之间的冲突。

对于经常使用 WordPress 进行开发、插件维护和网站管理的开发者来说，这是一套比较实用的 Windows 本地开发工作流。

额外建议

文章发布前，我建议保留三个关键知识点，尤其是这三个地方比较容易被读者误解：

  1. PHP版本选择：WP-CLI 和 WordPress 对 PHP 版本有最低要求，下载时应结合当前项目的兼容性选择，不要盲目追求最新版本。
  2. LocalWP环境隔离：LocalWP Shell 的 PHP 和数据库配置不等于 Windows 全局配置，这是本文最重要的实践经验之一。
  3. 输入D:的原理：这是 Windows CMD 的磁盘当前目录记忆机制，而不是 LocalWP 自动识别 WordPress 项目。这样解释更准确，也更有技术参考价值。
