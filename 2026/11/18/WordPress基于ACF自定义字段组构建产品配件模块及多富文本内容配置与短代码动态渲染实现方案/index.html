WordPress基于ACF自定义字段组构建产品配件模块及多富文本内容配置与短代码动态渲染实现方案

发表于2026-11-18|更新于2026-11-18|wordpress

一、方案介绍

在 WordPress 产品详情页开发过程中，经常需要为不同产品配置独立的配件展示内容。如果直接在页面模板中编写固定 HTML，不仅后期维护不方便，也难以满足不同产品之间的内容差异化需求。

本方案通过 WordPress ACF（Advanced Custom Fields）插件 创建独立的 Group 自定义字段组，在产品后台提供多个 WYSIWYG 富文本编辑器，用于维护不同配件卡片的图片、标题、描述及图片跳转链接。

前端则通过自定义 Shortcode（短代码）读取当前产品对应的 ACF 字段数据，并按照预设的 UI 设计方案动态生成配件展示模块。

整个方案将后台内容管理与前端布局渲染分离，实现产品配件模块的独立维护和复用。

核心实现思路

功能模块 实现方式
后台字段管理 ACF Group 自定义字段组
配件内容编辑 多个 WYSIWYG 富文本编辑器
数据读取 WordPress get_field()
前端调用 自定义 Shortcode
页面结构 PHP 动态生成 HTML
样式控制 独立 CSS 样式前缀
响应式布局 PC 双列、移动端单列

前端布局效果

PC 端采用两列卡片布局，每张卡片内部采用图片左侧、文字右侧的横向结构。

移动端自动切换为单列布局，图片位于文字上方，卡片宽度自适应屏幕。

卡片支持鼠标悬浮边框高亮效果，图片可以单独配置跳转链接。

二、前置准备工作

开始部署前，需要确保具备以下条件：

  1. WordPress 网站已经安装并启用 Advanced Custom Fields（ACF）插件。
  2. 可以访问网站服务器文件，或者使用主题后台文件管理器。
  3. 建议使用子主题部署所有 PHP 代码，避免主题更新时造成代码丢失。
  4. 已经明确产品文章类型及配件模块的前端设计方案。

三、ACF 后台自定义字段配置

本方案通过一个 Group 字段组统一管理产品配件内容，内部配置四个 WYSIWYG 富文本编辑器，每个编辑器对应一张配件卡片。

3.2 设置字段组显示规则

在字段组的位置规则中，将显示条件设置为需要使用该模块的产品文章类型。

例如：

  • 文章类型：Product
  • 规则：文章类型等于 Product

这样在编辑对应产品时，后台就会自动显示配件模块的字段配置区域。

配置项目 设置内容

字段类型 Group
字段名称 lier_essential_accessories

3.4 创建四个富文本子字段

进入 Group 字段内部，依次创建以下四个子字段。

字段标签 字段名称 字段类型
配件卡片一 lier_essential_accessories_card_one WYSIWYG Editor
配件卡片二 lier_essential_accessories_card_two WYSIWYG Editor
配件卡片三 lier_essential_accessories_card_three WYSIWYG Editor
配件卡片四 lier_essential_accessories_card_four WYSIWYG Editor

四个字段的类型全部选择 WYSIWYG Editor（所见即所得富文本编辑器）。

完成配置后保存字段组。

此时进入产品编辑页面，就可以在后台看到四个独立的富文本编辑区域。

3.5 后台内容填写方式

每个富文本编辑器对应一张前端配件卡片。

建议按照以下顺序填写：

  1. 插入配件图片。
  2. 根据需要为图片添加跳转链接。
  3. 在图片后面输入配件标题。
  4. 输入配件描述内容。

每个富文本框独立维护一张卡片，不需要展示的卡片直接留空即可。

六、后台产品配件内容填写规范

短代码部署完成后，进入需要配置配件模块的产品编辑页面。

找到 ACF 创建的四个富文本编辑器，按照以下规范填写内容。

6.1 配件图片配置

在富文本编辑器中插入图片。

建议使用正方形图片素材，以便卡片在不同屏幕尺寸下保持良好的视觉效果。

如果需要让图片支持点击跳转，可以在 WordPress 富文本编辑器中为图片添加超链接。

6.2 配件标题和描述

图片后面依次填写配件名称及相关描述。

例如：

Ice Storage Bin

Designed for efficient ice storage and convenient daily operation.

实际内容根据产品配件类型进行调整。

6.3 空白卡片处理

如果当前产品只有两种配件，只需要填写前两个富文本编辑器即可。

剩余编辑器保持空白，前端会自动跳过未填写的字段，不会生成空白卡片。

七、前端样式与布局说明

本方案通过独立 CSS 类名前缀控制配件模块样式，减少与 WordPress 主题及其他页面组件之间的样式冲突。

7.1 PC 端双列布局

PC 端采用 CSS Grid 实现两列卡片排列。

每张卡片内部采用 Flex 布局：

  • 左侧展示配件图片。
  • 右侧展示配件标题和描述。
  • 卡片之间保持 24px 间距。
  • 卡片圆角设置为 16px。
  • 默认边框颜色为 #e2e8f0。

7.2 移动端单列布局

当浏览器视口宽度小于等于 768px 时，自动切换为单列布局。

具体变化：

  • 卡片由横向布局切换为纵向布局。
  • 图片移动到文字上方。
  • 图片宽度调整为容器宽度。
  • 卡片文字居中显示。
  • 模块容器取消左右内边距。

九、常见问题排查

9.1 配件模块不显示

检查以下内容：

  1. ACF 字段组是否已经启用。
  2. Group 字段名称是否为 lier_essential_accessories。
  3. 四个子字段名称是否与 PHP 代码一致。
  4. 当前产品是否已经填写富文本内容。
  5. 短代码 PHP 文件是否成功引入。

9.2 前端样式错乱

检查主题是否存在全局 CSS 样式覆盖。

本方案使用独立类名前缀 lier_accessiories_dus_，可以降低与其他组件之间的样式冲突。

9.3 配件图片不显示

重点检查：

  1. 图片地址是否有效。
  2. 图片是否成功插入富文本编辑器。
  3. 图片是否按照要求放置在富文本内容前面。
  4. 图片 HTML 是否符合当前 PHP 正则表达式的匹配格式。

9.4 移动端布局异常

检查媒体查询是否正常生效。

如果网站使用了页面缓存、CSS 压缩或 CDN，建议清除相关缓存后重新测试。

十、后期维护与样式修改

后期如果需要调整配件模块的视觉效果，可以直接修改 PHP 文件中的 CSS 样式。

常见调整位置如下：

修改需求 对应 CSS 选择器或属性
修改悬浮边框颜色 .lier_accessiories_dus_card:hover
修改卡片内边距 .lier_accessiories_dus_card
修改容器最大宽度 .lier_accessiories_dus_container
修改主标题字号 .lier_accessiories_dus_header h2
修改副标题字号 .lier_accessiories_dus_subtitle
修改卡片标题字号 .lier_accessiories_dus_textbox h3
修改卡片描述字号 .lier_accessiories_dus_textbox p
修改卡片间距 .lier_accessiories_dus_grid
修改移动端断点 @media (max-width: 768px)

如果需要修改悬浮边框颜色，建议同步检查 CSS 和 JavaScript 中的颜色设置，避免两处样式不一致。

十一、方案总结

通过 WordPress ACF 自定义字段组与 PHP Shortcode 相结合，可以实现产品配件模块的独立内容管理和前端动态渲染。

整个方案不需要为每个产品单独编写 HTML，也不需要重复修改页面模板。

后台只负责维护产品配件内容，前端短代码负责读取数据并按照统一的设计规范输出页面结构。

本方案的主要优势：

  1. 内容管理独立化：每个产品拥有独立的配件内容配置区域。
  2. 前端组件化：通过短代码即可在不同页面位置调用配件模块。
  3. 布局统一化：所有产品共享同一套前端结构和样式。
  4. 内容维护便捷化：运营人员可以直接通过后台富文本编辑器维护配件图片、标题及描述。
  5. 后期扩展灵活化：可以根据实际需求增加配件卡片数量、调整布局方式或扩展短代码参数。

整体实现了从 ACF 后台内容录入、PHP 数据读取到前端模块动态渲染的完整流程，适用于工业设备、制冰机、机械设备及其他具有配件展示需求的 WordPress 产品详情页。

另外提醒两个原代码中的技术细节，正式上线前建议修正：

  1. 当前 PHP 使用正则表达式解析富文本 HTML，对图片外层存在额外属性、HTML 格式变化等情况可能不够健壮。后期建议改用 DOMDocument 解析 HTML。
  2. 当前移动端图片容器设置了 height: auto，但图片本身仍然设置 height: 100%，可能导致图片高度异常。建议移动端将图片设置为 height: auto，并使用 aspect-ratio 控制图片比例。

这两个问题不影响文章的整体结构，但会影响实际部署后的兼容性和稳定性。
