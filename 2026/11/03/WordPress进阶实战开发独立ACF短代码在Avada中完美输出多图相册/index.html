WordPress进阶实战开发独立ACF短代码在Avada中完美输出多图相册

发表于2026-11-03|更新于2026-11-03

前言：为什么多图字段需要独立短代码？

在之前的文章中，我们解决了 ACF 纯文本字段在 WooCommerce 产品列表页的自动展示问题。但在实际业务中，产品详情页往往需要展示多张高清细节图（例如包装图、细节拆解图）。

如果你在 ACF 中创建字段组（如 Product detail image），并使用了类似 Marbak Multi Image 这样的多图上传插件，你会发现它的数据结构与普通文本完全不同。

特别是当你在后台将 Return Format（返回格式）设置为 Image Array（图片数组） 时，get_field() 返回的是一个包含多个维度的复杂数组（包含图片 ID、URL、尺寸等）。如果我们沿用之前的纯文本短代码，前端只会输出一堆 Array 报错。

因此，我们需要单独编写一个专门处理“图片数组”的独立短代码，不仅要精准提取图片链接，还要兼顾前端排版和页面性能。

需求分析与设计思路

我们的目标是：

  1. 独立运行：与之前的列表页参数、纯文本短代码互不干扰，代码彻底解耦。
  2. 精准提取：针对 Image Array 格式，提取特定尺寸（如 large/full）的图片链接，而非直接加载原图，节省带宽。
  3. 性能优化：输出 <img> 标签时带上懒加载（lazy loading）属性。
  4. 样式友好：输出的 HTML 结构需带有特定的 Class，方便通过 CSS 做成美观的网格相册。

⚠️ 核心避坑：Name 与 Label 的区别

在编写和使用短代码之前，必须明确 ACF 字段的命名规则，这是新手最容易出错的地方：

  • Field Label（字段标签）：显示在 WordPress 后台给编辑人员看的，可以是中文或带空格的英文（例如：product single page detail image）。它不能用于代码调用。
  • Field Name（字段名称）：用于 PHP 代码、短代码中调用的唯一标识符。必须是英文、数字或下划线，且不能有空格（例如：lier_product_single_page_detail_image）。

👉 所以，我们在短代码里填写的 name，必须是自定义字段的 Name（字段名称），而不是 Label！

为什么这段代码更科学？

  1. 完美匹配 Image Array：因为你在后台设置了返回格式是数组，代码中通过 $image['sizes'][ $atts['size'] ] 能够精准提取 WordPress 自动生成的缩略图尺寸，而不是强行加载几兆的高清原图，极大地提升了页面加载速度。
